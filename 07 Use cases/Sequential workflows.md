Use **Previous / Next** when order matters but hierarchy would be misleading: procedures, learning paths, journal chains, process steps, travel itineraries or release sequences.

Sequential roles share the left/right visual regions with Friend/Challenger, but their ontology label preserves the difference in meaning. That makes it possible to keep lateral context and ordered flow on the same map.

A useful pattern is to keep the content hierarchy in Parent/Child and use Previous/Next only for the path through that content. The same note can therefore answer both “where does this belong?” and “what should I do next?”.

**Dates do not automatically mean Previous/Next.** Native Date fields now have a selectable fallback role; use `Previous`/`Next` only if the Date relationship genuinely expresses your sequence. See [[03 Build and edit/Date properties and daily notes|Date properties and daily notes]].
