# Build a help system like this vault

Want people to find an answer without reading a manual from beginning to end? Connect short, useful guides into a help graph with several paths to the same answer.

![[Assets/Screenshot - Reading relationships.png]]

*The help's own notes form a navigable map: broader guides, related explanations and a caveat surround a small example.*

This very vault is an example of **documentation as a navigable Plex**, not just a collection of pages.

## Keep the reader in the center

Begin each page with the reader's need and the result it helps achieve. Group large subjects into smaller topics: aim for no more than twelve direct children per note, including relationships declared from the child. Use Friend for useful neighboring guides and Challenger for a real caveat; reserve Previous/Next for a meaningful order.

## Four complementary structures

1. **Folders and section hubs** provide a normal reference outline.
2. **Ontology** provides Parent/Child navigation and Friend/Challenger cross-links between topics.
3. **Discovery routes** group existing notes by user goal through `Explains` fields; no copied content is needed.
4. **Previous/Next** orders real steps within help topics, without pretending that every reader follows the same path.

Hierarchical tags distinguish how-to notes, conceptual explanations, reference pages, cautions, examples and discovery paths. The supplied settings give these tags a visual style. Images and external URLs become first-class knowledge assets when their node types are enabled.

> [!tip] Avoid over-classifying
> Use explicit ontology for relationships whose meaning matters. Keep ordinary Markdown links for quick references, and use Challenger nodes for real caveats — not as a replacement for warnings in the text.
