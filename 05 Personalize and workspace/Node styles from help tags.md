This vault uses **tags as a visual grammar** so a graph node hints at the kind of help it contains before you open it.

| Style tag | Meaning in the help |
| --- | --- |
| `#kplex-help/home` | Main entrance |
| `#kplex-help/section` | Reference section hub |
| `#kplex-help/path` | Curated, task-based discovery route |
| `#kplex-help/concept` | Explanation of a concept |
| `#kplex-help/how-to` | Step-by-step action |
| `#kplex-help/reference` | Detailed reference |
| `#kplex-help/caution` | Important boundary or risk |
| `#kplex-help/example` | Use case or demonstration |
| `#kplex-help/about` | About the project and its community |

Topic tags (such as `#kplex/indexing` or `#kplex/navigation`) add a second way to browse and filter notes. A topic tag is not the same as the visual style tag.

K-Plex can also style nodes using a **Node style property** (default: `Note type`). Property-value styles are the current first-class system; imported tag-prefix styles remain supported and are deliberately used here. The **first matching imported tag style** determines that style when multiple style tags apply.

**Try it:** Visit [[00 Start Here/Choose a topic|Choose a topic]] and compare the look of a path, section, concept and how-to note. Then inspect **Settings → K-Plex → Visual styling → Node styling → Node styles**.
